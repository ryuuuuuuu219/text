# 会話と生成AI

## 観戦と通信ログ

俯瞰カメラで任意の機体を選ぶと、その周辺通信を優先表示する。別戦域で発生した会話は通信ログへ保存し、戦闘後に読み返せるようにする。

会話タイミングは、ブリーフィング、出撃前、発艦、敵発見、名乗り、敵エース遭遇、味方撃墜、救援要請、撤退命令、命令への反発、帰還、戦闘後、捕虜、再会、再戦など。

## 会話へ渡す状態

- 話者と相手の名前、所属、名声、性格、騎士道遵守率
- 好感度、過去の因縁、現在の任務
- 損傷、疲労、弾薬、燃料、G負荷
- 直前の確定イベント
- 会話目的、話者数、文字数、禁止事項

## 表現規則

古風な騎士口調ではなく、現代空戦を意識した短い無線を基本とする。航空騎士道は長広舌ではなく、名乗り、警告、攻撃許可確認、離脱宣言、降伏受理、救難保護という実務行動で示す。

- 方位、高度、距離、機数を短く報告する。
- コールサインと復唱を使う。
- 感情は短く挟む。
- 制度・倫理の長い説明はブリーフィングや帰投後へ回す。
- 現場は驚き、敵国への怒り、異常挙動、戦術対応、情報不足への不満を語る。
- 仕様解析、責任追跡、国連報告、証拠保全は司令部・情報部が扱う。

## 生成AIの責務境界

ゲームルール、登場者、装備、勝敗、戦果、死亡、捕虜、報酬はゲーム側が確定する。生成AIは許可された設定と確定状態を文章化するだけで、未知の国家・人物・兵器・出来事を追加しない。

推奨フロー：

1. ゲーム側がシードから構造化された作戦データを生成する。
2. 許可済みの設定・用語・人物だけを抽出する。
3. JSONまたは定型入力としてAIへ渡す。
4. AIが指定形式でブリーフィング・セリフ候補を返す。
5. ゲーム側が形式、未知語、文字数、話者、事実整合性を検証する。
6. 承認した文章だけを表示・保存する。

初期MVPは固定テンプレートで人物差を検証し、AI接続は後段階とする。
