整理すると、**表示シーンがかなり限定されているため、必要なテキストも大きく絞れます。**
現状の方針では、一般的なキャラクターゲーム用のプロフィールや日常会話を大量に用意する必要はありません。

## 1. 描画するシーン

使用するのは、次の5系統です。

### 戦闘時

* 俯瞰カメラ
* 艦載機オブジェクト上部の吹き出し
* 発言はログから再確認可能
* 表示名はコールサイン
* 例：
  `レイダー1：射撃位置についた`

### ブリーフィング／デブリーフィング

表示を切り替え可能。

**ボード表示**

* 作戦情報
* パイロットごとの戦果発表
* 画面端を埋めるように吹き出しを表示

**会議室俯瞰表示**

* ボード周辺に集まるパイロットを表示
* 各パイロット上部に吹き出しを表示

### 個人的な相談

* 会話ログ形式
* 表示するのは人物名とテキストのみ
* 人物名は艦長名またはコールサイン
* キャラクター立ち絵や背景差分は不要

主に撃墜された友軍機の救出嘆願

### 戦局のまとめ

* ドキュメンタリー映画風
* 地図グリッド
* 支配圏表示
* 画面下部字幕
* 主な語り手はナレーション
* 必要に応じて艦長の発言を挿入

### 戦闘区域選択
グリッドにランダムに出撃候補空域を点在させる
撃墜された友軍機がいる場合は前回の座標を保持

### その他

* 上記以外の専用シーンは描画しない
* 格納庫、食堂、私室、基地内部などの個別背景は作らない
* 人物図鑑や立ち絵鑑賞画面も現状は不要

# 2. パイロット基本情報

## 必要

* パイロット名
* コールサイン
* 所属国
* 所属組織
* 所属部隊
* 二つ名情報
* 性格情報
* 生存・負傷・撃墜などの現在状態
* 戦果情報
* 人物関係情報

以下は生成に任せる。

* パイロット名
* コールサイン
* 所属国
* 所属組織
* 所属部隊

## 省略

* 階級
* 役職
* 搭乗機の個別プロフィール
* 年齢
* 誕生日
* 身長
* 出身地
* 趣味
* 好物
* 詳細な経歴
* 人物紹介文
* 図鑑用プロフィール

ただし、階級を完全に省略するなら、**上官・部下という関係は階級ではなく人物関係データとして直接保持**する必要があります。

例：

```text
レイダー1 → レイダー隊長：上官
レイダー1 → レイダー2：同僚
レイダー1 → レイダー4：新人
```

# 3. 二つ名

二つ名は、単なる文字列ではなく構造体として保持します。

```csharp
public struct PilotEpithet
{
    public string epithet;
    public EpithetCondition condition;
    public string originText;
    public bool isAssigned;
}
```

想定項目は以下です。

* 二つ名本文
* 獲得条件
* 由来
* 誰が呼び始めたか
* 自軍側の呼称か敵軍側の呼称か
* 表示可能になったか
* 決定済みか

## 重要な仕様

* 一度決定された二つ名は変更しない
* 後から上位の条件を満たしても置き換えない
* 最初に成立した候補を採用する
* 同時成立時の優先順位を定義する
* 二つ名未獲得状態を許容する

必要なのは、**「いつ固定するか」**の明示です。

候補としては、

1. 条件達成直後
2. デブリーフィング開始時
3. デブリーフィング終了時

があります。

演出的には、**デブリーフィング時に戦果を集計し、そこで確定する**形が最も自然です。

また、二つ名が固定された後も、

* 二つ名が初めて公に呼ばれる場面
* 本人が認識する場面
* 敵側が二つ名を認識する場面

は別イベントとして扱えます。

# 4. 性格・口調

同じ性格の人物が似通うことは許容するため、複雑な個人別口調生成は不要です。

## 性格データ

* 性格タグ
* 一人称
* 二人称
* 敬語の有無
* 基本語尾
* 発言の長さ
* 感情表現の強弱
* 戦闘時に性格が変化するか
* 上官への口調
* 同僚への口調
* 新人への口調
* 敵への口調
* 禁止表現
* 頻出語
* 口癖

ただし、実装負荷を抑えるなら以下は統合できます。

| 元項目      | 統合先      |
| -------- | -------- |
| 一人称・二人称  | 呼称ルール    |
| 敬語の有無・語尾 | 口調タイプ    |
| 発言の長さ    | 短文・標準・長文 |
| 感情表現の強弱  | 感情表現レベル  |
| 頻出語・口癖   | 任意の追加語句  |
| 禁止表現     | セリフ生成制約  |

最小構成なら、次のようになります。

```text
性格タグ
口調タイプ
発言長
感情表現レベル
対上官口調
対同僚口調
対新人口調
対敵口調
口癖
禁止語
戦闘時変化
```

# 5. 戦闘時セリフ

## 使用する基本カテゴリ

### 戦闘開始・索敵

* 出撃時
* 敵発見
* 交戦開始
* 攻撃開始

### 攻撃

* 射撃位置についた
* 機銃射撃
* 命中確認
* 撃墜確認
* 撃墜失敗
* 攻撃中止
* 再攻撃開始

### 被攻撃・損傷

* 被弾
* 軽微損傷
* 重大損傷
* 回避開始
* 敵に追尾されている
* 敵を見失った
* 操縦困難
* 戦闘継続不能

### 支援・連携

* 援護要請
* 援護開始
* 援護への礼
* 攻撃指示への応答
* 防御指示への応答
* 編隊維持
* 編隊離脱
* 散開
* 集合
* ターゲット変更

### 資源・撤退

* 弾薬不足
* 弾薬切れ
* 燃料不足
* 撤退開始
* 撤退拒否
* 帰還

### 撃墜・決着

* 撃墜
* 脱出
* 味方撃墜への反応
* 隊長撃墜への反応
* 勝利
* 敗北

## 削除

* ミサイル発射
* ミサイル警報
* ミサイル回避
* ミサイル命中
* ミサイル残弾

ミサイル自体が騎士道法違反とされる世界なら、通常戦闘用セリフテーブルには含めません。

ただし、物語上「禁忌兵器が使用された」ときのために、通常無線とは別に、

* 禁忌兵器確認
* 命令違反への反応
* 敵の非騎士的行為への反応
* 作戦中止要求
* 艦長への報告

を特殊イベント用として置く余地はあります。

# 6. 敵との関係

以下はそのまま有用です。

* 強敵を認識
* 因縁の相手を発見
* 相手の二つ名を認識
* 敵を侮る
* 敵を警戒
* 敵を称賛
* 挑発される
* 挑発する
* 敵の戦法を分析
* 敵の撤退を確認

追加しておきたいのは以下です。

* 敵の撃墜数を認識
* 敵エースの参戦を報告
* 敵の戦法変化を認識
* 敵が味方を狙っていることを報告
* 敵の損傷状態を報告
* 敵が戦闘不能であることを確認
* 敵が降伏または離脱を試みた際の反応

ミサイルのない近距離空戦中心なら、特に次の状況が重要です。

* 背後を取った
* 背後を取られた
* 射線に入った
* 射線から外れた
* 正面衝突コース
* 旋回戦に入った
* 敵が失速した
* 敵が高度を失った
* 敵が編隊から孤立した

# 7. セリフ分類情報

挙げられた項目のうち、最初からすべてを実装すると重くなります。

## 必須

* セリフID
* セリフ種別
* 発言者
* 発言条件
* 優先度
* 再生確率
* クールダウン
* 対象
* 表示テキスト
* ミッション限定
* 初回限定
* 他セリフとの競合グループ

## 後回しでもよい

* 感情
* 緊迫度
* 戦闘フェーズ
* 味方用／敵用
* 通常／固有
* 単独時／編隊時
* 前後に接続できるセリフ

これらは発言条件やセリフ種別から推定できる場合があります。

特に、**感情と緊迫度は文章生成時には有用ですが、再生システム上は必須ではありません。**

最小構造は次のようになります。

```csharp
public class DialogueEntry
{
    public string id;
    public DialogueType type;

    public string text;

    public int priority;
    public float probability;
    public float cooldown;

    public bool firstTimeOnly;
    public string missionId;
    public string conflictGroup;
}
```

発言条件は、セリフデータ自身へ直接複雑な式を書くよりも、イベント側から種別を指定する方が扱いやすいです。

```text
敵を発見
    ↓
EnemyDetectedイベント発生
    ↓
EnemyDetectedカテゴリから発言候補を抽出
    ↓
人物関係・性格・クールダウンで絞り込み
    ↓
表示
```

# 8. 吹き出し表示で追加必須になる仕様

今回の表示方法では、文章内容だけでなく**画面上の競合制御**が重要です。

## 戦闘時

* 同時表示できる吹き出し数
* 同一人物が連続発言できる間隔
* 吹き出し表示時間
* 文字数による表示時間の延長
* 発言中に撃墜された場合の処理
* カメラ外の機体が発言した場合の処理
* 機体が重なった場合の吹き出し位置
* 発言者が画面外へ出た場合の処理
* 敵と味方で吹き出し様式を変えるか
* ログへ保存する範囲

## ボード／会議室

* 発言順
* 同時発言を許可するか
* 吹き出しが画面端を埋めた際の配置
* 発言者と吹き出しを線で接続するか
* ボード表示と俯瞰表示で同じ会話位置を維持するか
* 表示切替中も会話を進めるか
* 一時停止するか

この作品では、**音声がないため読み逃し対策が最重要**です。

必要になる機能は、

* 会話送り
* 一時停止
* ログ表示
* 既読速度変更
* 自動送り速度変更
* 戦闘中ログと会話ログの区別

です。

すべての関係に専用セリフを作る必要はありません。

## 保持する関係タグ

* 上官
* 同僚
* 新人
* 親しい
* 苦手
* ライバル
* 恩人
* 因縁
* 敵対
* 尊敬
* 保護対象

一人に対して複数タグが成立してもよいです。

```text
対象：レイダー2
関係：
- 同僚
- 親しい
- ライバル
```

## 関係性の数値

会話差分を生成するなら、タグに加えて簡単な数値を持たせると便利です。

* 親密度
* 信頼度
* 尊敬度
* 敵意
* 心配度

ただし、これを細かくシミュレーションしない場合は不要です。
今回の規模なら、**関係タグ＋関係段階**程度で十分です。

```text
無関心
認識
親交
信頼
強い結びつき
悪化
敵対
```

# 10. 成長・状態変化

列挙されている変化をすべて個別段階として持つと、組み合わせが急増します。

そのため、物語段階ではなく、複数の状態タグとして扱った方が安全です。

## 状態タグ

* 新人
* 実戦経験者
* エース
* 敗北直後
* 仲間を失った
* 負傷中
* 疲労
* 動揺
* 恐怖
* 自信
* 高揚
* 精神的消耗
* 覚悟
* 離反傾向
* 敵対化

たとえば、

```text
基本性格：慎重
状態：エース、仲間を失った、精神的消耗
```

のように重ねます。

ただし、全文を状態ごとに用意する必要はありません。

優先順位は、

1. ミッション固有
2. 人物関係固有
3. 状態固有
4. 性格別
5. 完全汎用

とすると扱いやすいです。

* 関係性変化イベント
* 精神状態イベント
* 作戦参加や離脱に関する相談

# 12. 艦長とナレーション

パイロット以外で必要なのは、この2種類です。

## 艦長

艦長は以下を担当します。

* ブリーフィング進行
* 作戦目標説明
* 出撃指示
* 撤退判断
* デブリーフィング進行
* 戦果評価
* 個人的な相談への応答
* パイロットの精神状態確認
* 二つ名や評判への反応
* 艦内方針の提示

艦長の名前は個人的な相談画面で表示します。

## ナレーション

ナレーションは以下を担当します。

* 戦局の時系列整理
* 地図上の変化説明
* 支配圏変化
* 作戦結果
* 人的・物的損害
* 戦争全体への影響
* 後世からの評価
* 次の章への接続

ナレーションはパイロットの感情を断定しすぎず、**記録映像・戦史資料のような距離感**を持たせると、ドキュメンタリー風の表示と整合します。

# 13. 追加で漏れていたもの

現状の方針から見て、まだ明示しておいた方がよいものがあります。

## 発言者の識別規則

場面によって表示名を切り替えます。

| 場面       | 表示名             |
| -------- | --------------- |
| 戦闘       | コールサイン          |
| ブリーフィング  | コールサイン          |
| デブリーフィング | コールサイン          |
| 個人的な相談   | 艦長名またはコールサイン    |
| 戦局まとめ    | ナレーション、必要時のみ艦長名 |

パイロットの本名をいつ表示するかも決める必要があります。

候補は、

* 常にコールサインのみ
* 個人的な相談だけ本名
* 初登場時だけ本名とコールサインを併記
* 本名は内部データだけに保持

です。

## 無言状態

発言しないことも性格表現になるため、

* 無反応
* 発言をためらう
* 発言を途中でやめる
* 吹き出しに「……」を出す
* 完全に表示しない

を区別した方がよいです。

## 発言の重複防止

複数人が同じ状況で同じ意味の発言をすると単調になります。

必要なのは、

* イベントごとの代表発言者選択
* 同一カテゴリの同時発言人数上限
* 同じ文章の連続禁止
* 同じ性格タイプの連続発言抑制
* 重要人物を優先する仕組み

です。

## 戦死・離脱後のデータ処理

* 以後の無線候補から除外
* ブリーフィングの参加者から除外
* 会議室上のオブジェクトを除外
* デブリーフィングでは撃墜報告対象として残す
* 戦局まとめでは記録として参照可能
* 過去ログの表示名は変更しない

## ログ用の追加情報

戦闘ログには表示テキストだけでなく、

* 発言時刻
* 発言者
* 所属
* 発言種別
* 発言対象
* 発生した戦闘イベント

を内部的に持たせると、後から検索・再生しやすくなります。
