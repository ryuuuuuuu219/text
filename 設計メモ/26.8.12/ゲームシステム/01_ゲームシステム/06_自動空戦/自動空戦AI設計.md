# 自動空戦AI設計

## 目的

各機が保有する情報と規定の範囲内で、索敵、目標選択、追尾機動、交戦継続を自動判断する。敵エースは空母への主要脅威であり、味方エースは火力に加えて名乗りや決闘で敵エースを拘束する防衛機構となる。騎士道を無視する敵は、この前提を逆用できる。

本書は「01_自動空戦の基本」から「04_機動・交戦判定」までの要点と、現在のMVP実装を統合した設計基準である。

## 判断順序

1. 作戦命令、通常戦闘規定、空戦規定から許可される行動を決める。
2. センサー、視界、天候、磁気擾乱、味方の報告共有から認識可能な対象を決める。
3. 任務、脅威、距離、名声、関係、戦術方針、性格から交戦目標を選ぶ。
4. 機体性能、操縦能力、速度、高度、損傷、疲労から追尾機動と交戦結果を決める。
5. 燃料、弾薬、損傷、疲労と戦況から交戦継続または離脱を決める。

## 現在のMVP

| 項目 | 現在の処理 | 将来反映する要素 |
| --- | --- | --- |
| 索敵・識別 | 敵味方、機体の索敵距離、パイロットの索敵半径で候補を限定。視野角による方向制限は設けない | 天候、磁気擾乱、情報共有、識別精度 |
| 目標維持 | 現在の目標が索敵距離内にいる限り維持。プレイヤーから選択基準の変更指示を受けた場合は再評価 | 任務変更、脅威急増、名乗り、決闘による割り込み |
| 目標再選択 | 0.25～30秒の更新間隔で状態を確認し、目標喪失時または指示変更時に選択基準から再捕捉。更新間隔はボタン操作1回につき0.25秒増減 | 性格、名声、関係、戦術方針による評価値 |
| 追尾機動 | 目標位置へ速度予測を加えた点を狙い、指令方向を平滑化 | 高度、エネルギー、武装射界を使う機動選択 |
| 操縦性能 | 機体の旋回性能とパイロットの疲労・負傷・短期スタミナを反映 | 熟練度、機体習熟度、G耐性 |
| スロットル | 水平飛行均衡速度を下回る場合に加速 | 戦術、燃料、離脱判断に応じた速度制御 |
| 交戦判定 | 未実装 | 射撃、命中、損傷、撃墜の判定 |

### 目標選択基準

目標選択基準はAIが自律変更する性格値ではなく、プレイヤーが飛行隊へ与える戦術指示とする。初期値は「対正面（現行）」とし、飛行隊一覧で選択中の飛行隊へ一括適用する。指示変更後は次のAI更新で各機が目標を再評価し、同じ敵が最適なら捕捉を継続する。

索敵距離内の敵は機体から見た方向を問わず、すべて目標候補とする。`trackingTargetId` が指定されている場合は出撃時の初期目標として優先し、その後はプレイヤーの選択基準に従う。

| 基準 | 選択規則 |
| --- | --- |
| 対正面（現行） | 機首正面との角度が最小の敵 |
| 対近距離 | 自機との距離が最短の敵 |
| 対遠距離 | 自機との距離が最長の敵 |
| カウンター | 自機を目標にしている敵を優先し、複数なら最も正面の敵。該当なしなら対正面 |

指示UIは[カメラ・観戦対象](../../02_プレイヤー体験/04_観戦・表示/01_カメラ・観戦対象/カメラ・観戦対象.md)で定義する。飛行隊が未選択の場合は操作できない。現在のMVPには選択基準と選択処理のみ存在し、プレイヤーUIから飛行隊へ指示を伝達する処理は未実装である。

### 実装責務

- `AircraftFlightAI`：索敵、目標保持、目標選択、更新周期の管理。
- `AircraftManeuverController`：速度予測点への追尾、操舵入力、スロットル入力の生成。
- `AircraftController`：操舵入力を機体性能と簡略空力へ反映。
- `PilotStatus`：索敵半径と操縦有効度を提供。

### 追跡優先・加速優先

追跡中は速度と減速度を物理更新ごとに観測し、次の2状態を切り替える。減速度は「前回速度－現在速度」を秒換算した正値とする。

| 状態 | 条件・動作 |
| --- | --- |
| 追跡優先 | 速度が速度閾値より高く、減速度が減速度閾値未満。ピッチ開始時の入力をパイロットステータスへ記憶し、旋回中に使用する |
| 加速優先 | 速度が速度閾値以下、減速度が減速度閾値以上、または短期スタミナがペナルティ閾値未満。スロットルを最大にし、ピッチ入力と記憶値を0へ減衰させる |

通常の状態切替後は、`0.5秒 + (1 - 短期スタミナ率) × 2秒` の再切替待ち時間を設ける。短期スタミナ欠乏による加速優先への切替だけは待ち時間を無視し、状態を確定してから操縦有効度による入力補正を行う。追跡対象が変わった場合は、以前の対象に対するピッチ入力記憶を消去する。

速度閾値と減速度閾値はパイロットごとの連続値として保持するため、遺伝的アルゴリズムの遺伝子へ利用できる。交叉・突然変異後は0以上へ制限し、撃墜・生存だけでなく、目標追従時間、速度維持、加速優先の滞在率、状態切替回数も適応度へ含める。短期スタミナ消費処理は別システムから呼ばれる前提であり、現状は自然回復と外部APIだけが実装済みである。

## 設計上の境界

- 戦闘結果、目標選択、交戦継続、離脱はゲームシステムが決定する。
- プレイヤーへの情報開示段階は[索敵・識別](../../02_プレイヤー体験/02_ミッション進行/03_索敵・識別/索敵・識別.md)で定義する。
- 撃墜後の生存・回収は[撃墜・救難ルール](../09_撃墜・救難/01_撃墜判定/撃墜・救難ルール.md)で定義する。
- 通信は確定済みの戦闘イベントを受け取り、検品済み候補を再生するだけで戦闘結果を変更しない。

## 設計状態

索敵、目標選択、単純追尾はMVP実装済み。命令・規定、天候・擾乱、名声・関係、決闘、武装を含む交戦判定は初期方針段階であり、計算式、数値、上限、UIは中核検証後に確定する。
